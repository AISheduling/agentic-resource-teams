# Ресурсное утверждение с источником

## Context and problem statement

Метод получает описание работы, где может не быть состава бригады, разрядов, оборудования и норм,
и возвращает **ресурсный режим**: кто, в каком составе, на чём и за какое время работает.
Сведения о ресурсах лежат в технологических картах, нормативных сборниках, профстандарте и истории выполнения, а значения в них расходятся. Выход должен:

- отделять написанное в документе от догадки модели;
- хранить для каждого утверждения источник, версию и место в источнике (страница PDF, пункт, цитата);
- не смешивать происхождение знания и результат его проверки;
- считать длительность одинаково для всех методов, чтобы разница метрик не зависела от арифметики;
- допускать несколько допустимых режимов для одной работы, а не одну «правильную строку»;
- явно показывать конфликт источников и «в источниках нет».

Пилотные данные: шесть пакетов работ `data/pacakges/PKG-01…06.yaml` (кирпичная кладка), реестр
`data/sources.yaml`. 
Метрики и условия сравнения — в ADR-0002.

## Considered options

1. Свободный текстовый ответ; один статус «верно / неверно»; один эталонный режим.
2. Структурированные утверждения с источником и локатором, но с одной осью статуса.
3. Структурированные утверждения с источником, версией и локатором; две независимые оси статуса
   (основание знания × результат проверки); режим из утверждений; длительность по фиксированной формуле;
   формальный чекер правил R1–R9; эталон — несколько допустимых режимов.

## Decision outcome

Выбран вариант 3.

### Файлы

- `data/sources.yaml` — реестр источников: `id`, `title`, `role` (`norm` / `example` / `standard` / `history`),
  `format`, `volume`, `access`, `license`, `url`, `used_in`, `decision`.
- `data/pacakges/PKG-<NN>.yaml` — пакет работы: `input`, `sources`, `gold` (`claims`, `derived`,
  `admissible_modes`, `not_found`, `traps`), `pass_criteria`, `open_for_expert`.

### Утверждение (`gold.claims[]`)

Утверждение — одно проверяемое высказывание о ресурсе. Режим собирается из утверждений.

| Поле | Обязательно | По умолчанию | Смысл |
|---|---|---|---|
| `id` | да | — | `C<n>`, уникален в пакете |
| `entity` | да | — | о чём утверждение (например, звено «двойка» на стене 380 мм) |
| `attribute` | да | — | какое свойство (состав звена, норма затрат труда, кран) |
| `value` | да | — | значение; число или текст |
| `unit` | нет | `null` | единица (чел.-ч/м3, маш.-ч/м3, разряд) |
| `src` | да для `mandatory` | — | `{doc, pdf_page, section, quote}`: `doc` — id из `sources.yaml`; `pdf_page` — номер страницы PDF (первая страница = 1); `section` — пункт или таблица; `quote` — дословная цитата. У `basis: expert` — `null` |
| `version` | нет | из реестра | издание, год, редакция; берётся из `sources.yaml` |
| `validity_period` | нет | `null` | период действия, если источник его даёт |
| `applicability` | нет | `null` | условия применимости (высота этажа, сезон, материал стены) |
| `basis` | да | — | основание знания (ось 1, ниже) |
| `check` | да | — | результат проверки (ось 2, ниже) |
| `mandatory` | да | — | `true` — обязательное требование; `false` — справка или ориентир |
| `conflict_with` | нет | — | id утверждений, с которыми источники расходятся; обязательно при `check: conflict` |

Способ получения (прямо написано, посчитано, взято из похожей работы, предположение модели) в пилоте
задаётся полем `basis` и блоком `derived`: посчитанное хранится в `gold.derived` и источником не
заявляется. Поля `unit`, `validity_period`, `applicability` и `version` при отсутствии значения
пишутся как `null`, а не пропускаются.

### Две независимые оси статуса

| Ось | Значения | Смысл |
|---|---|---|
| `basis` — основание знания | `document`, `observation`, `expert`, `llm_hypothesis` | откуда взялось утверждение: прямо в документе; из истории выполнения; со слов эксперта; предположение модели |
| `check` — результат проверки | `not_checked`, `confirmed`, `confirmed_partly`, `refuted`, `conflict` | что показала проверка: не проверено; подтверждено в полном объёме; подтверждено частично или в части условий; опровергнуто; источники противоречат друг другу |

Оси независимы. Сочетания, которые одна ось не различает:

| `basis` | `check` | Смысл |
|---|---|---|
| `llm_hypothesis` | `confirmed` | модель предположила, и это нашлось в документе: случай, ради которого нужен агент |
| `llm_hypothesis` | `not_checked` | опасная зона: догадка без подтверждения |
| `document` | `conflict` | два документа говорят разное (например, два издания ГЭСН) |
| `document` | `refuted` | документ устарел или не применим к условиям |
| `expert` | `not_checked` | мнение эксперта, не сверенное с документами |

Правило: утверждение с `basis: llm_hypothesis` не может быть выдано как `mandatory`, пока у него нет
хотя бы `confirmed_partly`. Метрика «доля неподтверждённых обязательных требований» считается по
утверждениям с `mandatory: true`, у которых `check` не `confirmed`; строгий или мягкий вариант
(засчитывать ли `confirmed_partly`) фиксируется в ADR-0005 до первого эксперимента.

### Режим (`gold.admissible_modes[]`)

Режим — набор утверждений, собранный в одну команду, пригодную для планирования.

| Поле | Обязательно | Смысл |
|---|---|---|
| `mode_id` | да | `M<n>`, уникален в пакете |
| `roles` | да | `[{role, grade, count}]`: роль, разряд, численность |
| `equipment` | нет | оборудование и число экземпляров |
| `conditions` | нет | условия, при которых режим действителен (сезон, подача материалов) |
| `labor` / `labor_variants` | да | расчёт `{q, n, k, H, m, eta, d_hours, d_shifts_8h}`; `labor_variants` — по одному расчёту на каждое значение нормы из расходящихся источников |
| `supported_by` | да | id утверждений, из которых режим собран (трассируемость) |
| `admissible` | да | `true`, `conditional` (нужен эксперт) или `false` |
| `why` | нет | пояснение, почему режим допустим или условен |

### Длительность по фиксированной формуле

- `H = q · n · k` — общая трудоёмкость, чел.-ч. `q` — объём работ в единице нормы (м3, м2, шт.), `n` —
  затраты труда на единицу объёма (из ГЭСН, карты, ЕНиР), `k` — коэффициент условий работ (например,
  зимний 1,13; без особых условий `k = 1`).
- `d ≈ H / m` при `η = 1` — длительность, ч. `m` — число работников, одновременно выполняющих работу;
  `η` — эффективность совместной работы, принятая равной 1 (идеальная совместная работа без потерь на
  координацию, простои и ожидание материалов).

`η = 1` — упрощение, что любую работу можно ускорить пропорционально числу людей.
Состав бригады и возможность параллельной работы должны быть допустимы для выбранной работы (в карте это размер звена). 

Пример условия: 100 м2 × 0,5 чел.-ч/м2 × `k = 1` → `H = 50` чел.-ч; для бригады из 5 человек
`d ≈ 10` ч. Пример из PKG-01: `H = 10 · 5,21 · 1,0 = 52,1` чел.-ч; при `m = 2` `d ≈ 26,05` ч,
около 3,3 смены по 8 ч.

Все методы получают формулу из одного кода и различаются только тем, что подставляют в `q, n, k, m`.

### Формальный чекер

Чекер — программа без языковой модели, которая проверяет режим по явным правилам.

| № | Правило | Пример ошибки |
|---|---|---|
| R1 | покрытие обязательных ролей: все роли, обязательные для работы (по нормативу и профстандарту), присутствуют | нет звеньевого каменщика высокого разряда |
| R2 | совместимость роли и разряда по профстандарту, допустимая замена | каменщик 2 разр. поставлен на работу, требующую 4 разр. |
| R3 | совместимость роли и оборудования | кран есть, машиниста нет |
| R4 | число и мощность экземпляров оборудования: нужное не больше доступного, производительность не ниже потребности | один кран на три звена, который не успевает подавать материал |
| R5 | один человек = один человек: человек с двумя навыками считается один раз, сумма `count` равна `m` | «каменщик + такелажник» записаны как два человека, а это один |
| R6 | арифметика: `H = q·n·k`, `d ≈ H/m`, единицы совпадают | в карте 10 каменщиков, а в расчёте `m = 4`; перепутаны м2 и м3 |
| R7 | применимость условий: условия утверждения не противоречат условиям работы | зимняя норма в летней работе |
| R8 | трассируемость: у каждого обязательного утверждения есть `src` и `version`, а `quote` находится на указанной странице | требование без ссылки |
| R9 | статусы: нет `mandatory` + `llm_hypothesis` без подтверждения; `conflict` не скрыт | догадка выдана как обязательное требование |

Чекер принципиально не ловит:

1. Смысл цитаты: он проверяет, что страница и текст существуют, но не что текст утверждает именно это.
2. Неизвестные неизвестные: обязательную роль, которой нет ни в источниках, ни в правилах.
3. Реальную осуществимость на площадке (люди, погода, поставки, захватки). `η = 1` по определению:
   формула не проверяет, что `m` человек действительно могут работать параллельно.
4. Оптимальность: чекер говорит «допустимо», а не «лучше всех».
5. Устаревшие нормы, которые выглядят корректно, если версия не закодирована.
6. Терминологические расхождения вне словаря нормализации («каменщик» и «кладчик»).
7. Скоррелированные ошибки, если правила чекера написаны с помощью языковой модели; R1–R9 пишутся вручную.
8. Юридическую и охранную сторону (допуски, удостоверения) вне закодированных правил.



### Эталон и сравнение

- Эталон пакета хранит несколько допустимых режимов (`admissible_modes`), а не одну «правильную строку».
- Оценка идёт по допустимости (R1–R9 и эксперт), а не по точному совпадению.
- `not_found` — то, чего нет в источниках: метод обязан назвать это неизвестным и не придумывать.
- `traps` — правдоподобные, но неприменимые значения, которые метод не должен брать.
- Пакет типа `negative` (PKG-07) хранит `absence_checks`: правильный ответ «в источниках нет».

### Принятые упрощения

- Норма ГЭСН даёт затраты труда на всех рабочих-строителей, а состав звена в карте включает только
  каменщиков; допущение фиксируется в ограничениях работы.
- Расчёт длительности даётся для каждого значения нормы отдельно (`labor_variants`), без усреднения.
- Реестр источников хранит версии на уровне документа; `version` утверждения берётся оттуда.

### Consequences

- Все методы (правила, ближайший шаблон, RAG, агент) обязаны выдавать утверждения и режимы в этом формате,
  иначе их нельзя сравнить.
- Нужны реализации: `schema.py` (поля утверждения и режима), `checker.py` (R1–R9), `formulas.py` (`H`, `d`).
- Ошибочное обязательное утверждение портит несколько режимов, поэтому справочные значения не помечаются
  `mandatory` «на всякий случай».
- Эксперт нужен для применимости нормы, допустимости замен и смысла цитаты: чекер этого не закрывает.


## Pros and cons of the options

- **Свободный текст, один статус, один эталон.** Просто получить, но результат нельзя проверить и
  сравнить, статус смешивает происхождение и проверку, а единственный эталонный режим противоречит
  тому, что допустимых команд несколько.
- **Структура с одной осью статуса.** Проверяема, но не различает «догадка модели, подтверждённая
  документом» и «догадка без подтверждения»: именно это различие нужно для метрики неподтверждённых
  требований.
- **Структура с двумя осями, фиксированной формулой и чекером.** Требует ручной разметки источников и
  локаторов и написания правил чекера, но делает результат проверяемым, отделяет эффект сбора знаний от
  арифметики и позволяет сравнивать методы по допустимости.
